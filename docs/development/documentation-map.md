# Documentation map

Which document describes which artefact, and how each claim is verified. The source of truth
is `tools/weave_workflow/docmap.json`; the section between the markers below is generated
from it by `python3 -m tools.weave_workflow docs-map --write`, and the drift audit fails if it
is stale. Policy for using the map: [documentation-currency.md](documentation-currency.md).

How to read the impact rules: when a change touches a path in "Triggered by" (other than a
document itself), every listed document must be updated in the same change, or carry a
`not-applicable` entry with a justification in the task's DOCS_IMPACT list. `{component}`
means the README of the component that changed. Documents alone do not trigger rules; they
are covered by the path, command, claim, boundary and vocabulary checks.

Verification methods:

- **generated**: produced by a script and compared with a fresh run;
- **tested**: compared with tool output (counts, hashes, codes, commands, paths) by the audit;
- **manually reviewed**: checked by the local and independent reviewers against the impact list.
